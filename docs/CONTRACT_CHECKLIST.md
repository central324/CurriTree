# API·데이터 계약 합의 체크리스트

> **상태: 초안.** 팀원 3명이 논의한 후 필드명과 반환 형식을 확정합니다. 이 문서는 아직 최종 API 명세가 아닙니다.

## 1. 교육과정 JSON

- [ ] 학과 ID 표기 방식 확정
- [ ] 교육과정 기준 연도 및 적용 학번 구분 방법 확정
- [ ] 과목의 고유 ID, 이름, 학점, 이수구분 필드명 확정
- [ ] 권장 학년·학기 및 실제 개설 학기 구분
- [ ] 필수 선수 관계와 권장 관계의 구분 방식 확정
- [ ] 진로 태그 목록과 유효값 확정
- [ ] 졸업요건 중 1차 버전에서 실제로 판정할 항목 확정
- [ ] 출처 URL 및 최종 확인일 기록 방식 확정

## 2. 수강 계획 데이터

- [ ] 이수 완료 과목과 수강 예정 과목 구분
- [ ] 학기 표현 형식 합의 (예: `2027-1`)
- [ ] 전공 외 학점 입력 및 확인 불가 항목 처리
- [ ] 중복 과목·재수강 처리 범위 결정
- [ ] 공유 링크에서 저장하는 데이터와 조회 코드 정책 확정

## 3. API 계약

| 메서드 | 경로 | 담당 |
| --- | --- | --- |
| `GET` | `/api/departments` | 팀원 A |
| `GET` | `/api/curriculum/:dept` | 팀원 A |
| `POST` | `/api/validate` | 팀원 B |
| `POST` | `/api/plans` | 팀원 C |
| `GET` | `/api/plans/:code` | 팀원 C |
| `POST` | `/api/ai/plan` | 팀원 C (확장) |

각 API에 대해 다음 항목을 문서화합니다.

- [ ] 정상 요청 예시 JSON
- [ ] 성공 응답 예시 JSON
- [ ] 입력 검증 실패 응답 및 HTTP 상태 코드
- [ ] 데이터가 없거나 판정할 수 없는 경우의 표현
- [ ] 서버와 클라이언트가 공유할 계산 규칙

## 4. 협업

- [ ] 전체 팀원이 데이터 형식과 API 계약을 검토함
- [ ] 변경이 필요한 경우 관련 팀원과 먼저 합의함
- [ ] 합의된 계약에 대한 테스트 케이스 작성
